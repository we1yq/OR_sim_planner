Fixes between the evidence runs and the final runs: E1 sender calls
`gc.freeze()` every second (live_traffic_20260926.py); transformers runtime
marks TTFT inside the single `generate()` call instead of an extra prefill
forward (`*-ttft-20260929` images); router forms batches pull-based
(`e1c-20260929`).

Files: `requests.csv.gz` (final runs only) holds the per-request fields the
analysis needs (compact_requests.py); the raw `requests.jsonl` /
`planned_requests.csv` are not committed.  `analysis/` is produced by

    python3 e1_analyze.py <run>    # E1 tables + vision time series + ledger
    python3 s46_analyze.py <run>   # 4.6 action durations, makespan vs critical path, lock/route checks

The ledger in `analysis/ledger_capacity_per_second.csv` is rebuilt from the
route snapshots and the capacity_timeline event times, because the runner's
capacity_timeline.csv lacks replica profiles (`catalog_match_missing`).
LLM SLO: TTFT and TPOT are judged separately (client TTFT = router queueing +
network + runtime TTFT; TPOT = runtime TPOT).
